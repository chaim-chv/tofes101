# אשף מול עמוד אחד

## ההחלטה

**אשף של 8 שלבים + מסך סקירה.** לא עמוד אחד של 160 שדות, ולא 160 שלבים.

| שלב | תוכן | ~שדות |
| --- | --- | --- |
| 0 | פתיחה: מה זה, מה יקרה, "הנתונים נשארים במכשיר" | 0 |
| 1 | שנת מס + פרטי מעסיק | 3–6 |
| 2 | זהות: ת"ז/דרכון, שם, לידה, עלייה | 5–8 |
| 3 | מגורים וקשר: ישוב, רחוב, מיקוד, טלפון, אימייל | 5–7 |
| 4 | מעמד: מין, מצב משפחתי, תושבות, קיבוץ, קופ"ח | 4–6 |
| 5 | ילדים (אם רלוונטי) | 1–10 |
| 6 | נקודות זיכוי והכנסות אחרות | 3–8 |
| 7 | סקירה ותיקון | 0 |
| 8 | הצהרה, חתימה, ייצוא | 1–2 |

- שלב 5 מדולג לגמרי למי שמזוהה בדרכון — עם הסבר, לא היעלמות שקטה.
  → [[ux/required-optional-conditional]]
- כל שלב ≤ 8 שדות גלויים. אם שלב גדל, מפצלים אותו (למשל "ילדים" → "ילדים"
  + "פרטי ילד").

## למה לא עמוד אחד

- 160 שדות בעמוד אחד = עומס קוגניטיבי, אובדן מקום, וקושי אמיתי במובייל.
- שגיאה בשדה 3 מסכנת את כל הטופס; סיכום שגיאות למעלה רחוק מהשדה.
- קורא מסך: ניווט בין 160 שדות בלי מבנה שלבים הוא עינוי.
- מדידה: אי אפשר לדעת איפה נושרים.

## למה לא 160 שלבים

- כל מעבר שלב = קריאה מחדש של הכותרת, אובדן הקשר, ועלות ניווט.
- GOV.UK ממליץ "one thing per page" אבל מקבץ שאלות שתלויות זו בזו; שם "דבר"
  הוא *החלטה*, לא *שדה* ([מקור](kb/sources/govuk-question-pages.md)).

## הכללים שמחברים את זה

1. **כותרת = השאלה.** `<h1>` הוא "מה שמך?" ולא "שלב 2".
2. **התקדמות גלויה**: "שלב 2 מתוך 8" + רשימת שלבים עם `aria-current="step"`.
3. **ניווט חופשי אחורה**, וקדימה רק אחרי ולידציה של השלב.
4. **שמירה אוטומטית** בכל שינוי; "המשך מאוחר יותר" מייצר קישור.
5. **בלי מעבר אוטומטי** בבחירת רדיו — שינוי הקשר מפתיע (3.2.2).
6. **מסך סקירה** מציג את הטופס השלם כפי שיודפס, עם "ערוך" לכל סעיף.
7. **מצב "עמוד מלא"** לקוראים שרוצים לראות הכול: `/review?all=1`, לקריאה
   בלבד, עם קישורי עריכה. זה עונה על הצורך המשפטי "לראות את המסמך".
8. **Enter** בשלב מפעיל "המשך" רק כשאין שגיאה ואין רשימת השלמה פתוחה.
   → [[ux/keyboard-model]]

## סיכונים ומענה

| סיכון | מענה |
| --- | --- |
| משתמש לא מבין לאן נעלם שלב הילדים | הודעת "דילגנו על שלב זה משום ש…" + קישור "שנה סוג זיהוי" |
| אובדן נתונים במעבר | autosave סינכרוני לפני ניווט; even before route change |
| חזרה אחורה מהדפדפן | אותו מצב בדיוק; אל תשברו את Back |
| קישור ישיר לשלב | טעינת טיוטה + ולידציה של השלבים הקודמים, עם הודעה |
| קורא מסך לא יודע שהשלב השתנה | `h1` ממוקד + `aria-live="polite"` "שלב 3 מתוך 8: מגורים" |

## Do / Don't

| Do | Don't |
| --- | --- |
| 8 שלבים + סקירה | 160 שדות בעמוד אחד |
| ניווט שלבים גלוי | "הבא" בלבד בלי מושג איפה אני |
| שמירה לפני מעבר | מעבר שמאבד חצי דקה של הקלדה |
| דילוג מוסבר | העלמת שלב בשקט |
| סקירה כטופס שלם | "אישור" בלי לראות מה אישרתם |
